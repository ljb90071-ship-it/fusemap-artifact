# Reference input and execution

Each input JSON gives positive `rows` and `columns`, positive `lambda`, one candidate list per role, one metadata dictionary per role, and a fixed list of edges. Candidate `-1` denotes null and is always available. Nonnull column IDs cannot be reused across roles. Metadata values are decimal numbers parsed as exact rational values; their mean is S(m). Each edge has zero-based `i`, `j`, integer `base` (including the threshold), and a dictionary of signed integer contributions keyed by `role:column`. Omitted contributions are zero. Null contributes zero. All cached terms must share one score unit. The example uses integral units; the paper protocol separately specifies quantization by 10,000.

The objective is S(m) + lambda/min(rows,columns) times the maximum partial matching weight. Unmatched rows and columns have zero reward. The graph is fixed even for zero or negative weights. Isolated vertices contribute zero and need no solve. Components are ordered by their first edge in input order.

`assignment` uses a row/column-mask dynamic program. It derives nonnegative dual prices by relaxing the complementary-slackness difference constraints of the optimal matching. For a matched column j owned by row k, u_i >= u_k + w_ij - w_kj; for an unmatched column, u_i >= w_ij. The matching optimum rules out positive cycles. Matched-column prices are w_kj-u_k; unmatched-column prices are zero. Feasibility and equality of primal and dual objectives are asserted on every solve.

`bounds` computes the transferred repair, independent one-sided reset, and zero-price row/column maxima. The old matching rescored under new weights, capped below at zero, supplies a lower bound. The graph must remain unchanged when transferring a state.

`Problem.search` enumerates the metadata initializer for small inputs, generates valid single-role replacements and pair swaps, and processes neighbors lexicographically. Null sorts before real column IDs. Equality retains the current or first selected candidate. Candidate bounds are compared to the best fully evaluated neighbor. Unchanged components reuse exact states. Changed components are refined by descending upper-minus-lower gap, breaking ties by component index. Transfer mode attempts the one-sided reset before exact solution; zero mode uses the zero bound; full mode solves every changed component. Accepted candidates are exact. All modes use fresh exact component solves; no warm-start speed claim is made for this backend.

The library expects trusted, well-formed research inputs. It checks dimensions, unique edges and integer cache terms, but it is not a hardened general-purpose data ingestion service. Large candidate products and large components are outside its intended scale.

For clarity, this reference computes transfer, reset and zero bounds together in `bounds` for every candidate component, including unchanged components before reuse. It only applies the reset at the selected refinement step. This eager computation preserves selection semantics but differs from the paper implementation's deferred bound scans; reference counters count exact solves and cannot reproduce its timing or scan costs.

`decode(mapping)` performs a fresh solve for each component and returns globally sorted row pairs. `search` always calls it at its terminal schema. Its work is separate from the reported `initial_solves` and `candidate_solves` counters. This makes the reference output independent of intermediate primal/dual choices. The paper uses a common fresh min-cost-flow decoder for every common-score baseline; DP and flow can choose different tied optima, so reference row-pair identity is only claimed within this backend.

`alternating(start)` enumerates all feasible schema mappings for each fixed-row update, then solves the row block exactly. It retains each block on equality and repeats until no strict improvement. The returned row pairs are decoded afresh, using the same decoder as profiled search. This is a small-instance implementation of the full schema block, not a single-coordinate surrogate.

`restart_starts` uses the paper's average role-agreement penalty, includes null agreements, and excludes previous starts. `metadata_unit=1` is suitable for the example score units; use 10000 if metadata was multiplied by 10000. Starts optimize this modified additive metadata objective; every ensuing `alternating` run optimizes the original objective. `alternating_restarts` completes up to eight distinct starts and chooses the largest endpoint objective, retaining the first on equality. Exhausted finite spaces return fewer starts. The helper decodes each completed run for inspectable outputs, so its operations are not a model of production timing. The time-limited comparator is represented by its protocol and archived table, not by a wall-clock scheduler in this repository.
